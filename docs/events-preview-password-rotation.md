```powershell
node scripts/rotate-events-preview-from-file.mjs --apply-from-file "C:\Users\Andrei Zavtur\Downloads\env-rotated.txt"
```

Это описание следующего запуска, команда применения ещё не выполнялась. Скрипт:

1. Повторно проверяет существующий Vercel-проект, Vercel Authentication и точную область существующего секрета (только Preview, без Git-specific overrides). Команда CLI обновляет все окружения записи, поэтому точная область проверяется до изменения дважды.
2. Читает dotenv, полный PostgreSQL URL или скачанные PGUSER/PGPASSWORD. Для credentials-only использует старые endpoint/database только при совпадении роли. Не подбирает пароли и не пробует остальные файлы.
3. Требует новый пароль, отличный от старого, и тот же endpoint/database/роль; проверяет фактический Preview Branch ID только SELECT.
4. Пробует старый пароль через unpooled endpoint, чтобы не принять старую аутентифицированную сессию пула за новый вход. Требует явную ошибку PostgreSQL authentication (28P01/28000); сетевая ошибка не считается отзывом пароля. Если старый пароль принимается или результат неоднозначен — останавливается до изменения конфигураций.
5. Передаёт новый проверенный URL в Vercel CLI только через stdin, обновляя существующий Preview-only EVENTS_DATABASE_URL как Secret. Аргументы процесса, вывод и ошибки не содержат URL.
6. Обновляет только локальный NEON_DATABASE_URL через готовый repair-скрипт с повторным SELECT Branch ID; остальные строки сохраняются, приватный ACL остаётся на файле.
7. Проверяет локальное значение в памяти, повторно читает безопасные metadata Vercel, проверяет новый пароль и ветку. Vercel подтверждает запись секрета; его повторное чтение недоступно из-за Secret. Реальное внедрение в runtime подтверждает обязательный guard после отдельно разрешённого Preview deployment.

Изменения Vercel и локального файла не могут быть одной транзакцией. При частичном сбое скрипт сообщает только этап и флаги завершённых шагов, останавливается и ничего не развёртывает. Если Vercel уже обновлён, а локальный файл ещё нет, ту же команду можно повторить. После полного успеха повторный запуск потребует другого нового пароля и остановится; это защита от ложного подтверждения ротации.

Текущее локальное подключение до сброса — базовый старый пароль для проверки. Без знания пароля со скриншота невозможно отдельно доказать отзыв именно того более раннего значения; подтверждённый Reset password этой роли и отклонение сохранённого предыдущего пароля обеспечивают проверку текущей ротации.
