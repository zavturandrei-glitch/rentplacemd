# Проверка настоящей Neon и подготовка Preview

> Актуальное состояние после миграции и проверки Vercel: [подготовка Vercel Preview](events-vercel-preview-preparation.md) и [результат миграции](events-preview-migration-result.md). Ниже сохранён исторический порядок первоначальной подготовки: утверждения об отсутствующих таблицах и ожидании разрешения миграции устарели. Текущий блокер — скрытые удалённые Preview-подключения; deployment не выполнялся.

Дата: 29 октября 2026 года. CLI: **Vercel 65.7.0**, проверен запуск и справка команд. Ни push, ни deployment, ни применение миграции не выполнялись.

## Фактическое состояние — живая проверка выполнена

- Локальная NEON_DATABASE_URL корректна; соединение с PostgreSQL успешно. Значение и пароль не выводились.
- Сервер подтвердил transaction_read_only=on. Выполнены только SELECT-запросы к настройкам и каталогу таблиц.
- SQL-параметр neon.branch_id совпал с идентификатором **br-wild-band-b9c3gc4d**, который владелец предоставил из Neon Console для ветки preview. Сервер не раскрывает имя ветки через neon.branch_name; подтверждение основано на сопоставлении реального ID, а не на названии env-файла. Проверка с намеренно неверным ID корректно отклоняется.
- В information_schema текущего подключения не обнаружено пользовательских таблиц. Обе событийные таблицы отсутствуют, поэтому schemaReady=false — это ожидаемая неготовность схемы, а не ошибка соединения. Таблиц квартир, видео и занятости в этой Preview-базе не найдено. Production-базы не запрашивались.
- План миграции неизменен: 3 операции, две новые событийные таблицы и служебная запись ON CONFLICT DO NOTHING. DROP/ALTER/UPDATE/DELETE/TRUNCATE отсутствуют; данные и существующие таблицы не изменялись.
- Локальный файл имеет приватный ACL и исключён из Git. Общая DATABASE_URL и настройки Vercel не менялись. Миграция, git push и deployment не выполнялись.
- Следующий шаг требует отдельного разрешения владельца: применить только событийную миграцию к этой подтверждённой Preview-ветке. После этого повторить read-only check и проверить локальный календарь на порту 3001.

Машиночитаемый безопасный результат: [events-neon-check.json](events-neon-check.json).

## Какие подключения использует приложение

Runtime событий, по приоритету:

1. `EVENTS_DATABASE_URL` — явное переопределение.
2. `NEON_DATABASE_URL`.
3. `NEON_POSTGRES_URL`.
4. `NEON_DATABASE_URL_UNPOOLED`.
5. `NEON_POSTGRES_URL_NON_POOLING`.

Миграция дополнительно поддерживает `EVENTS_MIGRATION_DATABASE_URL` и предпочитает unpooled-варианты Neon. Общая `DATABASE_URL` не перезаписывается. В подготовленном Preview-runner старые общие подключения выключены **только в дочернем локальном процессе**; существующий `.env.local` не меняется. Настройки Production не меняются.

## 1. Подключение уже подтверждено

Владелец сохранил соединение отдельной Preview-ветки локально. Повторная авторизация, повторная выгрузка или пересоздание файла не нужны. Следующее действие — отдельное подтверждение применения миграции к ветке br-wild-band-b9c3gc4d. Команда безопасной повторной проверки:

```powershell
node scripts/run-events-preview.mjs check --expected-branch-id=br-wild-band-b9c3gc4d
node scripts/run-events-preview.mjs plan
```

Сейчас check возвращает connected=true/readOnly=true и ненулевой код из-за отсутствующих таблиц. Применение SQL этими командами невозможно.

## 2. Выгрузка через CLI: проверенный путь и ограничение Sensitive

```powershell
pwsh -NoProfile -File .\scripts\pull-events-preview.ps1
```

Если проект принадлежит другой команде Vercel, укажите **реальный** slug/ID этой команды:

```powershell
pwsh -NoProfile -File .\scripts\pull-events-preview.ps1 -VercelScope 'actual-team-slug'
```

Сейчас повторно запускать выгрузку не нужно: ограничение Sensitive подтверждено, шаблон уже существует. Команды ниже сохранены для окружений с доступными для выгрузки подключениями.

`actual-team-slug` — обозначение для замены, а не предположение об аккаунте владельца. Сценарий запрашивает существующий проект `rentplacemd`, не создаёт проекты и не публикует сайт. Если выбранный scope неверен, сценарий останавливается.

Внутри вызывается проверенная команда CLI:

```text
npx --yes vercel@65.7.0 env pull <новый-приватный-временный-файл> --environment=preview --project=rentplacemd --yes
```

Это описание внутреннего вызова. Используйте готовый PowerShell-сценарий: он создаёт файлы с доступом текущего Windows-пользователя, подавляет сообщения CLI, сохраняет только необходимые строки подключения в `.env.events.preview.local`, удаляет временный файл и печатает только имена переменных. `--yes` разрешает заменить исключительно созданный им пустой временный файл. Существующие `.env.local` и Preview-файл не перезаписываются. Production-переменные не запрашиваются; CRON_SECRET и ADMIN_PASSWORD в новый файл не копируются.

Наличие переменных в окружениях Production/Preview **не доказывает, что это разные ветки Neon**. Кроме того, при автоматическом Preview Branching часть значений может вводиться лишь при deployment и отсутствовать в `env pull`. Если нужного подключения нет, сценарий откажется продолжать: нужно выбрать отдельную ветку в Neon и получить её соединение безопасным способом. Не копируйте Production-строку в Preview ради обхода проверки.

## 3. Реальная проверка только на чтение

```powershell
node scripts/run-events-preview.mjs check
node scripts/run-events-preview.mjs plan
```

`check` выполняет SELECT в read-only транзакциях и выводит только `connected`, `readOnly`, `schemaReady` и имя выбранной переменной. Ни URL, ни пароли не печатаются. `plan` не применяет SQL. Runner исключает старые подключения из унаследованного окружения, проверяет совпадение runtime/unpooled-целей, не допускает общий DATABASE_URL и не имеет команды применения миграции.

Ожидаемые состояния:

| Результат | Следующее действие |
| --- | --- |
| `connected: true`, `schemaReady: true` | Можно проверять локальный календарь с настоящими данными. |
| `connected: true`, `schemaReady: false` | Нужна подтверждённая миграция отдельной Preview-ветки. |
| Нет подключения / ошибка | Не публиковать и не применять миграцию; проверить доступность Preview-переменных и права. |

## 4. Подтверждение миграции Preview

Перед применением владелец подтверждает:

- выбранная Neon-ветка изолирована от Production;
- разрешено создать две событийные таблицы и служебную запись в этой ветке;
- `runtime` и `migration` относятся к одной Preview-базе.

Точная SQL-миграция: `migrations/20261029_events.sql`. В этой сессии она **не применялась**. Команды применения намеренно не включены в автоматический Preview-runner. После подтверждения используется существующий инструмент с `--apply --target=preview` и проверенным Preview-окружением. Production-режим запрещён текущим заданием.

## 5. Проверка локального календаря с настоящей базой

Только после успешного `check` и готовности схемы:

```powershell
node scripts/run-events-preview.mjs build
node scripts/run-events-preview.mjs serve
```

Календарь: `http://127.0.0.1:3001/events`. Сервер привязан только к localhost. Проверить пять языков, реальные опубликованные изменения, месяцы/архив, страницы событий, `/sitemap.xml` и закрытую админку. В этом read-only проходе не нажимать сохранение/импорт/обновление и не запускать Cron: они записывают состояние. Создание/редактирование тестовых событий в Preview требует отдельного разрешения владельца.

## 6. Подготовка Preview deployment — требует разрешения

После авторизации и проверки файлов можно выполнить **только инспекцию без загрузки**:

```powershell
npx --yes vercel@65.7.0 deploy --dry --environment=preview --project=rentplacemd
```

При другом scope добавляется `--scope` с подтверждённой командой. Этот dry-run пока не завершён: CLI требует входа. `.vercelignore` явно исключает файлы окружения и локальную идентификацию CLI.

Перед публикацией владелец подтверждает проект/scope, готовность отдельной Neon-ветки, Preview-переменные и включённую защиту Preview (Vercel Authentication). Эти настройки кабинета не менялись.

**Только после отдельного разрешения на Preview deployment:**

```powershell
npx --yes vercel@65.7.0 deploy --environment=preview --project=rentplacemd --yes
```

Команда подготовлена, но не запускалась. Не добавлять `--prod`, `--create-if-missing`, `--verify` или git push. Последний `--verify` может создавать дополнительный bypass-секрет; он не нужен для этого этапа. Для защищённой проверки адрес открывает авторизованный владелец.

## Что подтвердить владельцу

1. Подключение и ветка уже подтверждены. Сейчас требуется отдельное разрешение создать две событийные таблицы и служебную запись только в этой Preview-ветке.
2. Перед записью — подтвердить изоляцию Preview-ветки и применение только событийной миграции.
3. Перед тестами с записью — разрешить временные тестовые записи только в Preview, если потребуется.
4. Перед внешней публикацией — отдельно разрешить Preview deployment и подтвердить его защиту.

Production-миграции, git push и production-публикация в этот план не входят.
