# Готовность защищённого Preview — 29 октября 2026

## Подтверждено

- Свежая выгрузка только Vercel Preview содержит `EVENTS_DATABASE_URL`. Её значение скрыто как Secret/Sensitive; в отчёте сохранены только имя и признак недоступности значения. Production не запрашивалась.
- Календарь выбирает `EVENTS_DATABASE_URL` перед всеми `NEON_*`. Общий `DATABASE_URL` не изменяется. Квартиры, занятость и видео не используют EVENTS_DATABASE_URL; их код выбора подключения этим этапом не менялся.
- SQL Branch ID для локального Preview-подключения совпадает с `br-wild-band-b9c3gc4d`. Это не доказательство содержимого секрета Vercel: удалённое значение станет проверяемым только при запуске с ним.
- Новая проверка при старте Node.js Preview выполняет только SELECT в read-only транзакции. Совпадение ID и `transaction_read_only=on` обязательны. Ошибка, недоступность сервера, отсутствие ID и другая ветка блокируют запуск. Ошибки драйвера заменяются общим сообщением без URL и пароля.
- Все обращения календаря через `eventSql()` также ожидают этот guard, включая CRUD, изображения и cron. Успешная проверка кешируется в экземпляре процесса для выбранного URL; при изменении URL или неудаче выполняется повторно. PostgreSQL-запрос к неверной базе ограничен чтением идентификатора, до чтения/записи событий дело не дойдёт.
- При `VERCEL_ENV=production` и локальной development проверка не подключается к базе и не меняет поведение старых хранилищ. Production-деплой не выполнялся.
- Административный `/api/admin/events/health` теперь возвращает безопасное поле `previewBranch` с результатом проверки, ожидаемым ID и read-only-флагом. Доступ по-прежнему требует существующего входа администратора. При ошибке — HTTP 503 без секретов.

## Что требуется для тестовой версии

1. Владелец подтверждает, что Preview EVENTS_DATABASE_URL скопирована именно из ветки `br-wild-band-b9c3gc4d` и нет Git-specific overrides. Secret через CLI не читается; наличие переменной уже проверено. Старые NEON_* могут остаться неизменными: календарь использует новый override.
2. Убедиться в выборе правильной команды/проекта rentplacemd и включённой защите Preview. Эти настройки кабинета не менялись.
3. Дать отдельное разрешение на **Preview deployment**. Подготовленная команда (не запускалась):

```powershell
npx --yes vercel@65.7.0 deploy --environment=preview --project=rentplacemd --yes
```

При необходимости добавить только подтверждённый `--scope`. Не применять `--prod`/`--prebuilt` и не передавать секреты аргументами. Автоматической миграции нет.

4. При старте реального Preview guard проверит именно внедрённый Vercel Secret. Если ID неверен, тестовая версия не должна обслуживать запросы; исправить только Preview-секрет и повторить deployment после согласования. Локальная сборка не подтверждает удалённый секрет.
5. После успешного старта открыть Preview в браузере под защитой Vercel, затем проверить `/events`, пять языков, смену месяцев, SEO и защищённый admin health. Подтвердить `previewBranch.verified=true`, `schemaReady=true` и `connectionVariable=EVENTS_DATABASE_URL`. CRUD в размещённом Preview — отдельный тест с разрешения владельца.

Production-публикация и Production-миграция остаются отдельными действиями. Разрешённого внешнего источника событий нет: работает ручное управление и импорт. Vercel Cron нельзя считать проверенным на Production по результатам локального старта.
