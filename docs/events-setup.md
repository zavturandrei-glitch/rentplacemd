# Подключение календаря RentPlaceMD

Изменения подготовлены локально. По сообщению владельца Neon Free `rentplacemd-db` уже подключена к Vercel (Production и Preview), `CRON_SECRET` задан для Production, тариф — Hobby. Локальная сессия не получает переменные Vercel автоматически: фактическое соединение и production-планировщик здесь ещё не подтверждены. Публикация — только после подтверждения владельца.

## 1. Neon PostgreSQL

База Free `rentplacemd-db` уже создана владельцем. Для первой проверки убедитесь, что Preview использует отдельную ветку базы, а не Production. Дополнительные платные сервисы не нужны.

В Vercel → проект RentPlaceMD → Settings → Environment Variables добавьте переменные ниже. Секреты вставляйте непосредственно в Vercel, не в чат и не в репозиторий. Для локальной проверки — в игнорируемый `.env.local`.

| Переменная | Назначение |
| --- | --- |
| `NEON_DATABASE_URL` / `NEON_POSTGRES_URL` | Подключение событий, поступающее из интеграции Neon с префиксом. Не нужно копировать его в общую `DATABASE_URL`. |
| `NEON_DATABASE_URL_UNPOOLED` / `NEON_POSTGRES_URL_NON_POOLING` | Поддерживаются как запасное подключение и предпочтительный вариант миграции. |
| `EVENTS_DATABASE_URL` | Необязательное явное переопределение подключения событий. |
| `EVENTS_MIGRATION_DATABASE_URL` | Необязательное отдельное подключение только для ручной миграции. |
| `CRON_SECRET` | Случайный секрет минимум 32 символа; Vercel передаёт его в `Authorization: Bearer …`. |
| `ADMIN_PASSWORD` | Существующий пароль админки. Сохраните действующее значение. |
| `ADMIN_SESSION_SECRET` | Необязательный отдельный секрет подписи сессии. Его изменение завершает старые сессии. |
| `EVENTS_FEED_URL` | Оставьте пустым: подтверждённого разрешённого фида пока нет. |
| `EVENTS_FEED_ALLOWED_HOSTS` | Точные имена разрешённых хостов через запятую; без wildcard, портов и протокола. |
| `EVENTS_FEED_PERMISSION_CONFIRMED` | Оставьте пустым. `true` только после проверки разрешения на коммерческую публикацию. |
| `EVENTS_CRON_LOCAL_HOUR` | По умолчанию пусто. Для точного местного часа на подходящем тарифе — `06`, вместе с изменением расписания ниже. |

Приоритет событий: `EVENTS_DATABASE_URL` → `NEON_DATABASE_URL` → `NEON_POSTGRES_URL` → варианты unpooled. Общие `DATABASE_URL` и `POSTGRES_URL` используются событиями только при явном `EVENTS_ALLOW_SHARED_DATABASE=true`. Их значения не перезаписываются.

Защита старых функций: видео и занятость сохраняют приоритет `DATABASE_URL` / `POSTGRES_URL`; новая `NEON_DATABASE_URL` не активирует их автоматически. При необходимости задаются отдельные `CITY_VIDEOS_DATABASE_URL` и `AVAILABILITY_DATABASE_URL`. Если старая конфигурация использовала только `NEON_DATABASE_URL`, до публикации требуется явная привязка этих модулей к прежней базе либо `LEGACY_USE_NEON_DATABASE=true` **после проверки наличия их таблиц**. Не направляйте их в новую пустую базу календаря.

Сначала выполните `npm run db:check:events`: команда работает в read-only транзакциях и не печатает URL или пароли. `npm run db:migrate:events` теперь показывает **только план** (3 операции, checksum, имя переменной). Для применения на проверенной отдельной Preview-базе: `npm run db:migrate:events -- --apply --target=preview`. Либо выполните просмотренную `migrations/20261029_events.sql` в SQL Editor правильной Preview-ветки Neon. Миграция идемпотентна: создаёт две таблицы, не удаляет существующие данные. Исходные 42 события остаются в коде; изменения администратора накладываются поверх них в БД.

Production-режим инструмента дополнительно требует `--target=production` и отдельного подтверждающего флага; в этой сессии он не применялся. Не запускайте миграцию автоматически при каждом запросе или при сборке. Сначала миграция preview, затем проверка preview, затем — после разрешения владельца — production.

## 2. Администрирование

Откройте `/admin/events`, войдите существующим паролем. Ссылка также добавлена в админку видео. Кнопка «Проверить соединение Neon» вызывает защищённый read-only endpoint `/api/admin/events/health` и сообщает, нужны ли таблицы.

- Просматривайте опубликованные события, очередь и последние 200 записей журнала.
- Для нового события заполните постоянный slug, исходные русские тексты, дату, место, категорию и подтверждающую HTTPS-ссылку. Неизвестное время оставляйте пустым.
- Заполняйте другие языки только после проверки перевода. При редактировании исходного fallback отметьте проверенный перевод соответствующим флажком.
- Укажите подтверждённого организатора и полный адрес, если они известны. Без них Event JSON-LD не публикуется; сама страница события доступна.
- При переносе укажите новую и прежнюю даты. Если новая дата неизвестна, выберите статус «Перенесено, дата неизвестна».
- «Отменить» сохраняет URL и показывает предупреждение. Редактированием можно вернуть статус. Физического удаления исторических записей нет.
- Ручной JSON-импорт находится в админке: массив 1–100 записей, до 500 KB. Все элементы проверяются до изменения БД; ошибка одного элемента отклоняет пакет. Импортированные события сначала проверяются в очереди. Редактирование и сохранение кандидата также удаляет его из очереди.
- В разделе источников можно сохранить выключенную конфигурацию официального поставщика. Для включения JSON-фида нужны публичный адрес, ссылка на условия и подтверждение коммерческого использования. RSS/ICS помечены как требующие адаптера и не включаются автоматически. Источник, выключенный в админке, имеет приоритет над устаревшими переменными фида.

Изображения: используйте собственные или лицензированные WebP/AVIF/JPEG/PNG до 1 MB. Заполните ссылку на источник и основание использования. Данные сохраняются в Neon, а не во временную файловую систему Vercel. Сервер проверяет сигнатуру формата; SVG пользователя не принимает. Next Image выдаёт подходящий мобильному устройству размер и поддерживает WebP/AVIF. При ошибке загрузки показывается собственная обложка категории. Для больших объёмов фотографий в дальнейшем потребуется отдельное согласованное хранилище: не покупайте его автоматически.

## 3. Планировщик

В `vercel.json` подготовлен ежедневный запуск `/api/cron/events` в `04:00 UTC`. Это совместимое с ограничением ежедневной частоты расписание: зимой ориентировочно 06:00, летом 07:00 в Кишинёве. На Hobby Vercel допускает запуск внутри часа, поэтому обещать ровно 06:00 нельзя. Это ограничение платформы, а не проверенный production-запуск.

Если текущий тариф поддерживает несколько запусков в сутки и точность до минуты, для местных 06:00 замените расписание на `0 3,4 * * *` и задайте `EVENTS_CRON_LOCAL_HOUR=06`. Один из UTC-запусков будет пропущен по часовому поясу. Ничего не покупайте ради этой настройки без решения владельца. [Ограничения Vercel Cron](https://vercel.com/docs/cron-jobs/usage-and-pricing).

Обновление использует двухминутную аренду блокировки в PostgreSQL, случайный идентификатор блокировки, оптимистическую проверку версии при записи и дневной ключ успешного планового запуска. Повторный запрос не публикует события повторно. При ошибке фида опубликованные данные сохраняются. При недоступной настроенной БД сервер возвращает ошибку, а не скрывает сохранённые изменения под исходной копией.

Архив определяется по окончанию события и дате Europe/Chisinau; записи и месяцы не удаляются. Текущий месяц вычисляется при запросе и обновляется в открытой вкладке, без пересборки сайта.

Без фида проверка записывает режим `manual-only`, состояние архива, наличие сохранённых изображений и время запуска. Она **не означает**, что сведения перепроверены у организаторов. `verifiedAt` события меняется при подтверждении редактором.

## 4. Будущий разрешённый импорт

На 29.10.2026 документированного публичного API/RSS/ICS с подтверждённым правом коммерческого повторного использования у iTicket, Fest.md, Arena Chișinău и городского календаря не установлено. Пустой robots.txt не предоставляет такую лицензию. При HTTP 429 запросы прекращаются; обход ограничений не реализован.

Подготовлены интерфейс подключения в админке и изолированный JSON-адаптер `lib/eventFeed.ts`. Он принимает массив до 500 событий / 2 MB, делает один HTTPS-запрос с таймаутом 15 секунд, запрещает redirects, требует явного разрешения и списка хостов. HTML не парсится. RSS/ICS-адаптеры можно добавлять после подтверждения формата и условий конкретного поставщика; они пока не заявлены как работающие.

Формат одного элемента:

```json
{
  "slug": "provider-stable-event-id",
  "title": { "ru": "Подтверждённое название" },
  "description": { "ru": "Проверенное описание" },
  "venue": { "ru": "Подтверждённое место" },
  "startDate": "YYYY-MM-DD",
  "category": "concert",
  "status": "scheduled",
  "sourceName": "Поставщик",
  "sourceUrl": "https://provider.example/event"
}
```

Это описание формата, не событие для публикации. Дополнительные поля: `endDate`, `startTime`, `previousStartDate`, переводы `ro/en/uk/cs`, `address`, `organizer: { type, name, url }`, `ticketUrl`. Используйте стабильный slug поставщика при переносах. Отсутствие события в следующем фиде не считается отменой. Все новые и изменённые записи требуют подтверждения; непроверенный импорт не публикуется автоматически.

## 5. Приёмка перед публикацией

1. Выполнить миграцию на preview Neon; убедиться, что админка показывает постоянное хранилище.
2. Проверить добавление/редактирование настоящего события, отмену, перенос, загрузку разрешённого изображения, запись в журнал и сохранность после перезапуска. Проверить конфликт двух редакторов.
3. Проверить ручной запуск; затем один реальный вызов Vercel Cron и повторный вызов того же дня. Проверить 401 с неверным токеном и 503 без настроенного секрета/БД. Не выводить токен в логи или скриншоты.
4. Проверить отсутствие фида: статус `manual-only`, ноль автоматически опубликованных событий. После получения разрешения проверить очередь на тестовом ответе поставщика.
5. Запустить `npm test`, `npm run lint`, `npm run build`; на локальном production-сервере — `npm run test:events-http`.
6. После разрешения владельца опубликовать; проверить production robots, sitemap, Event разметку, закрытость админки и cron. Подключить Google Search Console / Bing Webmaster для индексации и полевых Core Web Vitals.

Живой Neon, успешное выполнение миграции, запуск production Cron и сохранение данных после serverless-перезапуска в текущей сессии не проверены: подключения отсутствуют. Локальная реализация и проверки не заменяют эту приёмку.

